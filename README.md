# Операционная Charité — AR-реконструкция

Статический сайт для учебного задания: интерактивная 3D-реконструкция операционной
университетской клиники Шарите (Charité, Берлин) с просмотром в браузере, AR на
Android/iPhone и генерацией QR-кода для публикации.

Модель — фотограмметрический скан, сделанный заранее. Сайт **не создаёт и не
редактирует геометрию**: он только загружает готовые `model.glb` и `model.usdz`.

---

## Быстрый старт

Открывать сайт нужно через HTTP-сервер, а не как `file://` — иначе браузер не
загрузит `.glb` из-за CORS.

```powershell
cd ar-interior-charite
python -m http.server 8000
```

Открыть: <http://localhost:8000/>

Страница QR: <http://localhost:8000/qr.html>

Страница настройки меток: <http://localhost:8000/?debug=1>

## Как заменить модель

1. Положите новый файл в `models/export/`:
   - `model.glb` — для браузера, Android и Scene Viewer;
   - `model.usdz` — для AR на iPhone (Quick Look).
2. Если имена файлов другие — поправьте пути в `js/config.js`:

```js
scene: {
  glb: "./models/export/model.glb",
  usdz: "./models/export/model.usdz",
  sizeLabel: "9.9 МБ",
  // ...
}
```

3. Обновите страницу. Прогресс загрузки и ошибки уже обрабатываются.

**Требования к модели:**
- glTF 2.0 (`.glb` или `.gltf` + текстуры), PBR: baseColor, metallic-roughness,
  normal/occlusion — просмотрщик поддерживает всё;
- пол модели на `y ≈ 0`, масштаб в метрах (для AR);
- текстуры 1–2K, итоговый `.glb` желательно до 10–15 МБ;
- для iPhone нужен `.usdz` с теми же материалами. В текущей модели есть только
  baseColor + roughness factor; normal/roughness-карты можно добавить позже —
  сайт их подхватит без правок.

## Метки и камера

Все метки и тексты лежат в `js/config.js`. Координаты — в метрах, в системе
координат glTF (Y — вверх). Если модель экспортирована из Blender, то
`glTF (x, y, z) = Blender (x, z, −y)`.

### Настройка через браузер

1. Откройте `http://localhost:8000/?debug=1`.
2. Выберите метку в панели слева.
3. Двигайте ползунки X/Y/Z и Nx/Ny/Nz — метка двигается в реальном времени.
4. Нажмите «Скопировать конфиг» и вставьте массив в `js/config.js`.
5. Нажмите «Скопировать камеру», чтобы получить текущие `cameraOrbit` и
   `cameraTarget`, и вставьте их в `scene`.

### Стартовая камера

Сайт должен открываться **внутри комнаты**, а не снаружи скана. Поэтому:

- `cameraTarget` — центр рабочей зоны;
- `cameraOrbit` — радиус 4–5 м, камера на уровне глаз;
- `disable-pan` — цель не уезжает;
- `minCameraOrbit` / `maxCameraOrbit` — радиус 0.6–4.7 м и угол 60–100°, чтобы
  камера не вылетала за стены и не уходила под пол. Радиус 4.7 м — максимум,
  при котором камера остаётся внутри комнаты при любом повороте вокруг цели.

Если камера цепляет стену или оборудование — уменьшите радиус или измените
`theta` через `?debug=1`.

### Нормали меток

`data-normal` — направление, в которое «смотрит» метка. Для стены это
направление внутрь комнаты, для шкафа и аппарата — от их передней панели к
камере, для табурета — вверх. Если метка исчезает при вращении, проверьте
нормаль.

## QR-код

1. Опубликуйте сайт (см. ниже).
2. Откройте `https://<user>.github.io/<repo>/qr.html`.
3. URL подставится автоматически из адреса страницы. При необходимости
   отредактируйте его вручную.
4. Скачайте PNG (512/1024/2048 px) или SVG.
5. «Печать» — печатная карточка A5 с QR, ссылкой и подписью.

QR кодирует **финальный** адрес сайта, поэтому генерировать его нужно после
деплоя. Если открыть `qr.html` как файл, появится предупреждение — укажите URL
вручную.

## Публикация на GitHub Pages

Проект самодостаточен: в нём нет `.blend`, исходных FBX и тяжёлых текстур —
только сайт и два файла модели.

1. Создайте **публичный** репозиторий, например `ar-interior-charite`.
2. Скопируйте в корень репозитория **содержимое** этой папки:
   `index.html`, `qr.html`, `css/`, `js/`, `vendor/`, `assets/`,
   `models/export/`, `README.md`, `.nojekyll`.
3. Выполните:

```powershell
git init
git add .
git commit -m "AR-реконструкция операционной Charité"
git branch -M main
git remote add origin https://github.com/<user>/ar-interior-charite.git
git push -u origin main
```

4. В GitHub: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
5. Дождитесь адреса `https://<user>.github.io/ar-interior-charite/`.
6. Откройте сайт, проверьте сцену, AR и `qr.html`.

**Важно:**
- GitHub Pages работает по HTTPS — это обязательно для WebXR. По локальной
  сети (`http://192.168...`) AR не запустится.
- `.glb` может отдаваться как `application/octet-stream`; model-viewer это
  обрабатывает нормально.
- `.usdz` на GitHub Pages отдаётся с MIME-типом `model/vnd.usdz+zip` — это
  корректный тип для AR Quick Look на iPhone (проверено).
- Лимит сайта GitHub Pages — 1 ГБ; 15 МБ модели в норме.
- Перед публикацией проверьте права на фотограмметрический скан и укажите
  источник.

## Проверка на устройствах

### ПК

- Chrome / Edge / Firefox: загрузка, вращение, зум, 5 меток, карточки, Esc,
  сброс вида, помощь.
- AR-кнопка на ПК обычно не появляется: в desktop-браузерах нет WebXR AR.
  Сцена, метки и QR-код при этом работают полностью.
- Консоль без ошибок и 404.

### Android

- Chrome: кнопка «Смотреть в AR» → WebXR (ARCore) или Scene Viewer.
- Сцена большая: уменьшите макет щипком, затем поставьте на пол.

### iPhone

- Safari: кнопка «Смотреть в AR» → AR Quick Look открывает `model.usdz`.
- Если USDZ нет или он битый, кнопка AR не появится — сцена останется
  доступной в 3D-просмотре.

### Адаптив

- 1440×900, 1024×768, 390×844 (iPhone), 360×800 (Android).
- На телефоне карточка — bottom sheet, тап-зоны ≥ 44 px, горизонтального
  скролла нет.

## PBR, Z-fighting и производительность

**PBR.** Просмотрщик поддерживает glTF PBR полностью: baseColor, metallic,
roughness, normal, occlusion, emissive. В текущей модели есть baseColor-текстуры
и roughness factor; если добавите карты — они заработают без изменений кода.

**Z-fighting.** Модель — фотограмметрический скан, окно и дверь входят в общий
меш. Если при вращении появится мерцание на стыках, разведите полигоны в
исходной модели или уменьшите `shadow-intensity` в `index.html`.

**Производительность.** 335k треугольников и 4 текстуры 1024² — комфортно для
ПК и современных телефонов. Первая загрузка ~10 МБ; на медленной сети виден
прогресс-бар. Если нужно быстрее — уменьшите текстуры, примените Draco или
децимацию (это уже работа с моделью, сайт менять не нужно).

## Ограничения AR

- HTML-метки и карточки работают в браузерном 3D-просмотре. В нативном AR
  (Scene Viewer / Quick Look) их нет — там сцена просто ставится в помещение.
- На iPhone AR возможен только через `.usdz` (Quick Look). WebXR Safari не
  поддерживает.
- Комната в модели ~12 × 13 м, поэтому в AR она ставится как макет: уменьшайте
  щипком.
- Для AR нужен HTTPS (GitHub Pages даёт его автоматически).
